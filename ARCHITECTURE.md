# Cinnabar Compiler Architecture

This document describes how the Cinnabar compiler (the Rust crate in this repository) is built internally. It is a technical companion to [`MANIFESTO.md`](MANIFESTO.md) (the normative *language* specification) and [`AGENTS.md`](AGENTS.md) (the repository's working conventions) — read those first if you haven't. This document describes what the *code* does, generated by reading the source directly.

## Pipeline overview

`src/main.rs` wires together one fixed, sequential pipeline:

```
module_loader::load
      │
      ▼
resolver::resolve
      │
      ▼
typecheck::typecheck
      │
      ▼
borrow::borrow_check
      │
      ▼
codegen::compile_and_link
      │
      ▼
  (optional --run)
```

Each stage returns typed, span-carrying diagnostics rendered via [`ariadne`](https://github.com/zesterer/ariadne); a failure at any stage halts the pipeline and prints one or more source-located reports. `--dump-ast` short-circuits after parsing and prints the AST instead of continuing.

The governing design rule (stated explicitly in `AGENTS.md` and enforced throughout the code) is the **Single-Fact Rule**: a fact is computed exactly once, by the stage responsible for it, and attached to the program representation for every later stage to read. Name resolution belongs to the resolver; types belong to the typechecker; linearity is computed once during typechecking and read (never recomputed) by the borrow checker and codegen. Two independent implementations of the same fact are treated as a standing correctness bug, even if they currently happen to agree.

## The core representation: a flat node arena

Unlike a typical Rust compiler, Cinnabar does **not** represent its AST, symbol table, or type information as recursive Rust enums (`enum Expr { ... }`) or heap-boxed trees. Instead, the entire compiler state is a small set of flat, allocation-only buffers:

- **`nodes: Vec<i64>`** — a single arena where every kind of entity (tokens, items, functions, params, struct fields, enum variants, match arms, types, expressions, statements, patterns, resolved symbols, canonical type descriptors, generic monomorphization instances, constant values, trait-dispatch facts, enum-variant-tag facts, struct-field-offset facts) is stored as a fixed-width row.
- **`names: Vec<String>`** — an interning table for identifiers and string data, addressed by integer id.
- **`lists: Vec<Vec<i64>>`** — an arena of variable-length integer lists (argument lists, item lists, field lists), addressed by list id.

Each row in `nodes` has a fixed stride (`NODE_STRIDE` fields: `NODE_TAG`, `NODE_FILE`, `NODE_START`, `NODE_END`, plus generic payload slots `NODE_A`..`NODE_F`). A row's meaning is determined by its `NODE_TAG` (e.g. `NODE_ITEM`, `NODE_TY`, `NODE_EXPR`, `NODE_SYM`, `NODE_TYINFO`, `NODE_TRAIT`, `NODE_FIELDKEY`) plus, for many tags, a secondary integer opcode stored in one of the payload slots (e.g. `ITEM_STRUCT`, `TY_REF`, `EXPR_BINARY`/`BIN_ADD`, `STMT_IF`). Generic accessor/mutator functions (`node_tag`, `node_a`..`node_f`, `node_set_*`) read and write these rows; there is no `Box<Node>`, no recursive Rust enum walking, and every reference between entities is an integer index into one of the three arenas.

This is a deliberate "struct of arrays" / data-oriented design, reinforced by strict crate-wide lints in `Cargo.toml` (`unwrap_used`, `expect_used`, `panic`, `todo`, `unimplemented`, `unreachable`, and `wildcard_enum_match_arm` are all denied, alongside hard `deny`s on `dead_code`, `unused_imports`, and `warnings` in general). In-code comments describe this explicitly as the shape a self-hosted Cinnabar compiler would eventually use to represent itself (see Manifesto principle 10, "The Compiler Is a Pure Pipeline Over a Flat Arena") — the architecture is not expected to change when the implementation language does.

Where a fact genuinely has no room in an entity's own row, it is piggybacked into an otherwise-unused payload slot of that same row (for example, a type descriptor's linearity flag lives in a normally-unused slot of its `NODE_TYINFO` row) rather than introduced as a separate side table — keeping the Single-Fact Rule intact without growing the number of arenas.

## Stage 1 — Module loading (`src/module_loader.rs`, ~226 lines)

`load()` reads the entry `.cnb` file, lexes and parses it, then performs a worklist walk discovering sibling modules. Cinnabar has no package manager: a `use X.y` statement whose first segment `X` is not a `mod` already declared in the current file is resolved to a sibling file `X.cnb` next to the importing file (`sibling_path`) and recursively parsed. The result is the root item list plus `ext_mods: Vec<(name_id, item_list_id)>` — one entry per externally loaded file — and the full list of `(path, source)` pairs used later for diagnostic rendering across files.

## Stage 2 — Lexing (`src/lexer.rs`, ~622 lines)

A hand-written byte-level scanner (`lex`/`lex_byte`) that writes `NODE_TOKEN` rows directly into the shared arena — there is no separate token type. It handles:

- Identifiers and keywords, with casing rules enforced later by the resolver (the lexer itself just tokenizes).
- Decimal and `0x` hex integer literals, stored as raw `u64` bit patterns; range-checking against the literal's eventually-adopted type happens in the typechecker, not the lexer.
- Double-quoted string literals, with the five escapes `\n`, `\t`, `\0`, `\"`, `\\` decoded here and any other escape rejected as a lexical error. Unescaped text is copied out of the source as whole `&str` runs rather than byte by byte, so multi-byte characters survive intact, and the decoded bytes are interned into the shared `names` table — the same arena identifiers use. That interning is load-bearing rather than incidental: equal literals get one name id, which is what lets codegen emit a single `.rodata` global per distinct literal. A literal does not span lines, so a missing closing quote reports once at the newline instead of consuming the rest of the file.
- Four comment forms: `#` (discarded), `#!` (doc comment, attached to the following item), `#| ... |#` (block, discarded), `#!| ... |#` (block doc). Block comments explicitly do not nest — encountering a nested opener inside a block comment is a hard lexical error, with enough tracking to still recover and locate the real outer closer.
- One- and two-character operators and punctuation.

Integer literal accumulation uses `checked_mul`/`checked_add` rather than wrapping, so overflow during lexing is caught rather than silently producing a wrong bit pattern.

## Stage 3 — Parsing (`src/parser.rs`, ~1448 lines)

A hand-rolled recursive-descent parser (no parser-generator or PEG crate) consuming the token rows left by the lexer and emitting `NODE_ITEM`/`NODE_FN`/`NODE_TY`/`NODE_EXPR`/`NODE_STMT`/`NODE_PAT` rows through small `alloc_*` helpers (`alloc_item`, `alloc_ty`, `alloc_expr`, ...). Indentation is not significant — blocks are closed with `end` keywords, and newlines act as statement separators (`skip_nl`), with multi-line expressions permitted inside any bracketed delimiter (`()`, `[]`, `{}`). The parser has line-based error recovery (`recover_line`) so a single malformed statement does not abort parsing of the rest of the file — multiple parse errors can be reported from one invocation.

## Stage 4 — Name resolution (`src/resolver.rs`, ~1498 lines)

`resolve()` builds a scope tree (`scopes: Vec<Vec<i64>>` plus parallel `parents`/`pubs`/`prefixes` vectors) with two separate namespaces, `NS_TYPE` and `NS_VALUE`. It:

1. Seeds built-in primitives and native surface declarations (`seed_builtins`/`seed_primitive`) — `Unit`, `Result`, `Option`, `DivError`, `IndexError`, `Bool`, and the ten fixed-width integer types.
2. Hoists every top-level declaration (`collect_item`/`insert_decl`), enforcing the language's compiler-checked casing rules at this point (`casing_ok`/`report_casing`) — a mis-cased identifier becomes a resolver error, never reaching the typechecker.
3. Wires in every externally-loaded sibling module's scope, using the `ext_mods` list produced by `module_loader`.
4. Resolves `use` imports, including `as` aliases (`resolve_import`/`rewrite_import`).
5. Walks every item, function, statement, expression, type, and pattern (`walk_item`, `walk_fn`, `walk_expr`, `walk_pattern`, `walk_type`), rewriting unresolved `EXPR_PATH`/`TY_PATH`/`PAT_PATH` name segments into resolved `NODE_SYM` references.

This is also where the program's entry point is identified and tagged (`SYM_FUN_MAIN`), so later stages read that tag instead of re-deriving "is this the main function" by name comparison.

## Stage 5 — Type checking (`src/typecheck.rs`, ~3900 lines — the largest file)

`typecheck()` runs as a sequence of explicit sub-passes over a shared `State`: `collect_types` → `check_fn_sigs_list` → `collect_consts` → ... → generic function-body checking. Typing is structural and unification-free, keyed by canonicalized **type keys**: `TYD_UNKNOWN/BUILTIN/STRUCT/ENUM/NATIVE/REF/REF_MUT/SLICE/ARRAY/PARAM/MONO` rows, interned and deduplicated via `canon_tyinfo`/`find_tyinfo_by`, with generic substitution implemented once and reused generically (`subst_key`/`subst_list`) rather than per call site.

Notable responsibilities of this stage:

- **Constant evaluation** — `const` initializers are evaluated at compile time.
- **Monomorphization bookkeeping** — one `NODE_INST` row is created per instantiated generic function.
- **Fact attachment for later stages** — `NODE_TRAIT` (trait dispatch target), `NODE_VARFACT` (enum variant tag), and `NODE_FIELDKEY` (struct field offset) rows are computed once here and read verbatim by the borrow checker and codegen.
- **Linearity inference** (`attach_linearity`/`linear_of`/`linear_members_of`) — every type key is marked linear or not: native handle types are linear by declaration; a struct or enum is linear if any member is; a generic type parameter is *conservatively* linear (its instantiation is unknown at definition time, so the only sound default is to require exactly-once consumption, per Manifesto principle 7). This flag is stored directly on the type descriptor row, not in a separate table.
- **Result-everywhere arithmetic and indexing** — `/` and `%` are checked for compile-time-provable-zero divisors (a hard error) and otherwise typed as `Result(T, DivError)` with Euclidean semantics; a compile-time-constant array index is range-checked and typed as the bare element type, while a runtime-computed index or any slice index is typed as `Result(T, IndexError)`.
- **No implicit conversions** — every arithmetic/comparison operator requires identical operand types; the only sanctioned type-level coercion is `&[T; N]` → `&[T]`. Integer *literals* are not values of a type yet, so they adopt one from context (an expected type, or a peer operand when only one side is a bare literal) before the sameness rule applies; `int_literal_expr`/`binary_operand_expected` implement that rule once and both `check_binary` and the constant folder call them, so the same text cannot type one way in a `const` and another in a `var`. A string literal adopts nothing: it is `&[U8]` and only that.

## Stage 6 — Borrow / linearity checking (`src/borrow.rs`, ~3274 lines)

`borrow_check()` is a flow-sensitive dataflow analysis over a control-flow graph built per function (block kinds `BLK_ENTRY`/`BLK_STMT`/`BLK_JOIN`/`BLK_EXIT`). It tracks, for every binding, a state (`ST_UNBOUND`/`ST_LIVE`/`ST_MOVED`/`ST_PARTIAL`) that transitions through a fixed set of operations extracted from each statement/expression: `OP_READ`, `OP_MOVE`, `OP_BORROW`, `OP_BORROW_M`, `OP_ASSIGN`, `OP_BIND`, `OP_EXIT`, `OP_RET_REF`, and continuation-tracking `OP_CONT_*` variants for `return`/`break`/`try`-propagation exit points. `apply_move` is the central state-transition function.

This stage enforces, purely from facts computed earlier (never by matching type names):

- **Linear consumption** — any value the typechecker marked linear must be consumed exactly once on every path out of its scope (fall-through, `return`, `break`, or `try` propagation). A moved value can be neither moved again nor *borrowed*: a borrow after the move reads a resource the move already released, which is the use-after-free shape (`deallocate(block)` then `read_u8(&block, 0)`, or closing a `File.Handle` then writing through it).
- **Aliasing exclusivity** — no two simultaneously live `&mut` borrows of the same place; no mutation through a shared `&` borrow; no move of a place while it is borrowed.
- **Partial-move tracking** — a struct with one linear field among several non-linear ones can have that field individually moved out and the rest of the struct remain usable, tracked at the field level rather than treating the whole struct as consumed.
- **Ambiguous-borrow rejection** — a function returning a borrow whose origin the checker cannot determine unambiguously among the inputs is rejected (Manifesto principle 5), pushing the programmer toward restructuring the API rather than annotating a lifetime. A borrow into static data (a string literal, or a `const` of a reference type) is the case with no input origin and no error: it emits no returned-borrow obligation at all, since there is no loan to trace and the bytes outlive every caller. The per-function summary carries this too — it records which input parameters a returned borrow derives from, and an *empty* set means "static", which is what lets one function forward another's static result instead of the borrow becoming untraceable at the call.

This file carries the densest set of user-facing English error strings in the codebase (e.g. *"cannot move linear element out of array by index: borrow with `&` or `&mut` instead"*, *"linear value is consumed on some paths but not on all paths"*) — borrow/linearity diagnostics are effectively the primary day-to-day UX surface of the language, since a well-typed-but-linearity-incorrect program is the most common way to fail to compile.

## Stage 7 — Code generation (`src/codegen/`)

- **`types.rs` (~319 lines)** — `llvm_type`/`build_type` lower canonical type keys to `inkwell` `BasicTypeEnum`s: builtins to LLVM integer/`i1` types, structs/enums to LLVM structs (tagged unions for enums, with payload layout derived from the declared variant order — never a hand-maintained name-keyed table), and native handles to opaque pointer-like types. Lowering is memoized by type-key index.
- **`emitter.rs` (~3559 lines)** — `emit_program` locates `main` (via the `SYM_FUN_MAIN` tag from resolution, not by name lookup), then monomorphizes and emits every reachable function (`get_or_emit_fn`), lowering expressions, statements, and match arms to `inkwell` builder calls. It implements the native/opaque operation surface — heap memory (`malloc`/`free` via `extern_fn`), BSD sockets (`socket`/`bind`/`listen`/`accept`/`send`/`close`, declared as real libc externs — Cinnabar's networking is a first-class native surface, not a userland abstraction), and `Vec`/`String`/`HashMap` intrinsics with `errno`-based error mapping (`__errno_location`) — all dispatched on `NAT_*` opcodes assigned once during resolution, never by string-comparing a function's name. Self-tail-recursive calls are marked `tail` at emission time (tailness propagates only through the value expression of a tail-positioned match arm, never through argument subexpressions or match scrutinees), which is what lets LLVM's `-O2` tail-call elimination deliver the language's O(1)-call-stack recursion guarantee with no runtime stack check anywhere in the emitted binary. The user's `main` (which may return a scalar exit code or an "exit-status enum") is wrapped in a real C `int main(void)`.
- **`mod.rs` (~258 lines)** — takes the printed LLVM IR text and shells out to `opt` (running the `default<O2>`-class module optimization pipeline), `llc -filetype=obj`, and `clang -static -nostdlib -no-pie` to assemble, optimize, and statically link the final executable in a per-process temp directory (`std::env::temp_dir()/cinnabar_<pid>/`), which is cleaned up afterward. The static link is against a **musl libc** staged into the compiler binary itself at *build* time (see below) — a compiled Cinnabar program has no dynamic-linker dependency and no dependency on the host's libc.
  String literals lower to `private unnamed_addr constant` byte arrays that land in `.rodata`, named from the literal's interned name id (`@.cnb.str.<id>`) so the module itself is the reuse table — two occurrences of the same text resolve to the same global with no side table to keep in step with the name arena. A literal materializes as the same `{ ptr, i64 }` slice value every other slice uses, and a `const` of type `&[U8]` goes through the identical path, since it folded to the same name id. Because the language has no overloading, `Terminal.print` accepts either `&Collections.String` or `&[U8]` by reading the (data, length) pair out of whichever representation the parameter's canonical type descriptor says it is — a handle pointer to load fields through, or the view itself.
- **the runtime layer in `emitter.rs`** — every native surface (`Memory`, `Terminal`, `File`, `Net`) lowers to an external C/POSIX function (`mmap`, `munmap`, `open`, `read`, `write`, `close`, `malloc`, `free`, the socket wrappers) rather than inline syscalls. `runtime_platform` classifies the module's triple into Linux, Darwin/BSD, or Windows; `runtime_constants` supplies the per-platform open/mmap flags and errno values (`EINTR`, `ENAMETOOLONG`); and `runtime_errno` picks the platform's errno accessor (`__errno_location` / `__error` / `_errno`). An unsupported triple is a compile error naming it, never a guessed flag value.
- **`error.rs` (~64 lines)** — a typed `CodegenError { span, kind: Builder | Io | Tool }`; codegen failures are never a Rust panic.

## Staging a static libc (`build.rs`)

When the `static-musl` feature is enabled on Linux, `build.rs` self-provisions musl: it downloads the pinned release tarball into `target/musl/cache/`, verifies its SHA-256, and compiles it with `clang` into `target/musl/build/<version>/<arch>/install/`. Discovery then checks, in order, the `MUSL_LIBC_A` environment variable (manual override), that self-provisioned cache, standard host musl paths, and rustc's own musl-target sysroot, and copies `libc.a`, `crt1.o`, `crti.o`, and `crtn.o` into `OUT_DIR` (atomically, via a temp-file-then-rename). `codegen/mod.rs` then `include_bytes!`s these into the compiler binary so a `--static` link needs no external libc at build time.

## CLI and diagnostics (`src/main.rs`, ~743 lines)

`main.rs` is the CLI driver (`clap`-based; see [`README.md`](README.md#using-the-compiler) for the flag table) plus a flat-array AST pretty-printer (`dump_program`) used by `--dump-ast`. `--emit-json` selects the machine-readable rendering of whatever the invocation produces — `src/emit_json.rs` — so that a consumer parses exactly one document per run whether the program was accepted or rejected. It wires the seven pipeline stages together verbatim and renders every diagnostic through a common `Diag = (String, file_id, start, end)` tuple type, using `ariadne`'s `Report`/`Label`/`Source` with an `FnCache` to look up source text across the (potentially multi-file) module set for accurate cross-file error rendering. `NO_FILE = -1` marks a genuinely source-less internal error (e.g. a fact about a compiler-synthesized wrapper), which is rendered honestly rather than pointing at a fabricated location — per the "Honest Diagnostics" goal in `MANIFESTO.md`, no stage is permitted to invent a placeholder `Span`.

## Build/dev environment

- **LLVM version**: pinned via `inkwell = { version = "0.9.0", features = ["llvm21-1"] }` in `Cargo.toml` — LLVM 21 is required, and `flake.nix`'s `llvm`/`clang` packages are kept in lockstep with it.
- **`flake.nix`** provides a Nix dev shell with `llvm`, `clang`, `libffi`, `libxml2`, the Rust toolchain (`cargo`/`rustc`/`rustfmt`/`clippy`), `pkg-config`, `semgrep`, `valgrind`, `gdb`, and — notably — `coq`, a proof assistant, hinting at aspirations toward formal verification work (echoing the Ada/SPARK reference material kept in `austral_refs/`). The shell hook disables Nix hardening flags and sets `RUST_BACKTRACE=full`.
- **`pre_commit_check.sh`** is the project's build/verification gate: `cargo check` → `cargo clippy -D warnings` → a custom Semgrep ruleset (`.semgrep.yml`, intentionally treated as an opaque black-box check per `AGENTS.md` — it is never to be read or edited to "make it pass") → `cargo test` → CLI smoke tests → compiling and `--dump-ast`-ing several fixtures → running the compiled `spec.cnb` reference binary and checking for exit `0` → running a battery of `EXPECT_REJECTED` negative fixtures. It must always be run inside `nix develop` (`nix develop --command ./pre_commit_check.sh`), since `cargo build`/`cargo clippy` fail outside that shell (no `llvm-config`/`llc`/`clang` on a bare host `PATH`).

## Testing corpus (`tests/`)

`tests/fixtures/` holds real `.cnb` programs used both as positive examples and as a negative-space specification: files like `tests/fixtures/repro/*.cnb` are borrow-checker edge cases (two live `&mut` of the same place, partial moves, dynamic-index double-move, etc.), each paired with an `EXPECT_OK`/`EXPECT_REJECTED` entry in `tests/repro_harness.rs`. `tests/fixtures/spec.cnb` is the single immutable reference-implementation fixture — never edited — that is simultaneously a language feature tour and an executable self-test. `tests/fixtures/multi_file/` demonstrates the sibling-module-file loading described in Stage 1, and `tests/fixtures/verify_math/` exercises the Euclidean division/modulo semantics described in Stage 5.

`tests/native_memory.rs` is the one test that reads the compiler's *output* rather than running it: it emits LLVM IR for a fixture and asserts properties that are stated literally in the IR — that `Memory.write_u8`/`read_u8` access exactly one byte, that `Memory.deallocate` frees the pointer in the handle's data field, and that every native-handle constructor zero-fills the full `{ ptr, i64, i64 }` layout before storing any field. This exists because an external memory checker cannot be pointed at a Cinnabar binary: the `-static -nostdlib -no-pie` link against the embedded musl leaves no dynamic section, so Valgrind's memcheck has no allocator to interpose on and reports zero allocations for a program that allocates (see ROADMAP Milestone 3). `tests/fixtures/repro/mem_byte_access.cnb` is the paired behavioural oracle, detecting a wide access as a clobbered neighbouring byte.

## Tooling over the attached facts

The pipeline is also exposed as a library (`src/lib.rs`), and everything under this heading is a *consumer* of the attachments the stages above already computed — none of it re-resolves a name, re-infers a type, or re-derives a layout with parallel logic:

- **`src/analysis.rs`** — `analyze()` runs load → resolve → typecheck → borrow over a file set, optionally overlaid with unsaved editor buffers (`module_loader::load_with_overlay`), and answers position queries: hover (attached type key + resolved signature + linearity), go-to-definition and find-references (following resolver symbol ids across the module graph), completion (resolver-attached `NODE_SCOPEFACT` visibility/member rows, typechecker-attached `NODE_LOCALFACT` lexical snapshots, struct fields after `.` via `NODE_FIELDKEY` facts, keywords), and signature help. Includes byte-offset ↔ line/UTF-16-column mapping for LSP interop.
- **`src/bin/cinnabar_lsp.rs`** — the `cinnabar-lsp` binary: a JSON-RPC shell (via `lsp-server`) around `analysis`, with full-document sync. It maps every open module back to its analysis root, owns published URI sets per root, debounces checks off the protocol loop, and rejects stale generations before publication. The borrow checker's explanatory notes ride along as LSP `relatedInformation` and code lenses.
- **`src/inspect.rs`** — `--dump-typed-ast`: serializes the entire arena (names, lists, node rows) with symbolic tags and every attachment rendered. A row's meaning is extracted once, into a `RowDetail`, and rendered twice — as the line-oriented text a terminal reads and as the object `--emit-json` writes — so the two spellings cannot drift apart.
- **`src/codegen/layout.rs`** — `--print-layout`: ABI sizes/alignments/field offsets measured through the same `llvm_type` lowering and `TargetData` a real build uses; variant tags read from `NODE_VARFACT`. `measure_all` runs the measurement once and both the text report and the `--emit-json` document format its result.
- **`src/emit_json.rs`** — `--emit-json`: the machine-readable rendering of the surfaces above, one JSON document per invocation. It owns the version tag of each document (`cinnabar.ast.v1`, `cinnabar.typed-ast.v1`, `cinnabar.layout.v1`, `cinnabar.diagnostics.v1`), the shape of a source span, and the diagnostic envelope; the facts themselves come from the files that already own them. Spans carry byte offsets *and* the line/UTF-16 column pair mapped through `analysis::offset_to_position`, the same one the language server uses, and a fact with no Cinnabar origin renders `"source": null` rather than a fabricated location.
- **Borrow explainer** — the borrow checker records `Note` rows (`ast.rs`) tied to each error: per-predecessor consumed/live spans on join inconsistencies (from the converged dataflow's own exit states), binding sites with rendered linear types on unconsumed-at-exit errors, and prior same-block move sites on use-after-move. The CLI renders them under `--explain-borrow`; the LSP always sends them; the structured envelope carries them as each diagnostic's `explanations`, which is what `--explain-borrow=json` has always emitted and what `--emit-json` now emits for every stage.
- **`--emit-llvm` / `--emit-obj`** — stop the backend after IR emission or after `opt`+`llc`, for inspecting exactly what a real build feeds forward.
